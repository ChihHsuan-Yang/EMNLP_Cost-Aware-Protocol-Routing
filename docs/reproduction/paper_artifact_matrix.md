# Paper-to-code matrix

Every principal table and figure in the paper, with the public data it comes
from, how (or whether) this repository regenerates it, and how far a result may
drift before it counts as a failure.

**Read the `Command` line carefully.** Only some rows have a packaged
one-command regeneration path. The rest are published as aggregates that were
verified against per-problem data during release preparation, but that this
repository does not yet rebuild with a single command. Those rows say so
explicitly rather than pointing at a command that would not produce them.

`PER_PROBLEM_VERIFIED` means the published number was re-derived from released
per-problem data. `AGGREGATE_ONLY` means a lower-level artifact needed to
re-derive it independently is unavailable; see `TODO.md`.

Bootstrap confidence intervals are not expected to match exactly: they are
2,000-resample problem-level percentile intervals and their endpoints move in
the fourth decimal with the resampling seed. Point estimates are checked
strictly, with one documented exception — see
`../provenance/auprc_tie_handling.md` for why the AUPRC column is precise to
about two decimals rather than four.
